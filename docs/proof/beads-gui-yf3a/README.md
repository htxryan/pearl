# Proof — shadcn/ui + BaseUI primitive migration

**Meta-epic**: `beads-gui-yf3a` — *Adopt shadcn/ui with BaseUI primitives*
**Date**: 2026-04-25
**Method**: Playwright (chromium, headless, 1440×900 @ 2x retina) drove the live Vite dev server at `http://localhost:5173`.

This directory holds visual proof that every primitive migrated by epics E1a → IV is rendering and behaving correctly in the running app. Screenshots were generated by the scripts under `/scripts/proof-shadcn-baseui*.ts` (v1 = baseline; v2 = filter/dialog details; v3 = themes; v4 = AlertDialog + Sonner). The `_run-summary*.md` files record per-step status.

## Highlights — proof per epic

### E2 Atomic primitives — Button, Tooltip, Card, Badge, Avatar, Input, Separator, Skeleton, Label
- Buttons visible in every screenshot. Variants: `default` (purple Create Issue), `outline` (cancel), `destructive` (red Delete Issue), `ghost` (icon-only filter triggers). Sizes: `default`, `sm`, `icon`.
- See: `01-list-view-default.png`, `05-create-issue-dialog.png`, `v3-09-list-view-monokai.png`, `v4-04-alert-dialog-delete.png`.

### E3 Overlay primitives — Dialog, AlertDialog, DropdownMenu, Popover, Sheet, HoverCard
- **Dialog** (BaseUI portal-based, replacing native `<dialog>`): `05-create-issue-dialog.png`, `v3-10-create-dialog-monokai.png`. Backdrop scrim, focus trap, scroll lock all working.
- **AlertDialog** (replacing custom `confirm-dialog.tsx`): `v4-04-alert-dialog-delete.png` — "Delete issue permanently?" with Cancel + destructive-variant Delete Issue buttons.
- **DropdownMenu** (replacing custom): `10-detail-actions-menu.png`, `v2-14-actions-menu-dropdown.png`, `v4-03-actions-menu.png` — Claim / Close / Delete with destructive-variant red Delete row.
- **Popover** (notification panel migrated to Popover-anchored): `v3-02-notification-popover.png` — "Notifications" panel with bell icon and empty state.

### E4 Form primitives — Select, Combobox (single + multi via Chips), Calendar, Checkbox, RadioGroup, Switch
- **Select** (replacing custom `custom-select.tsx`): `v4-05-status-select-popover.png` — Open / In Progress (✓) / Closed / Deferred. Used in metadata sidebar Priority/Status/Type, board column headers, filter chips.
- **Combobox single** (replacing `assignee-picker.tsx`): the Assignee field in `05-create-issue-dialog.png`.
- **Combobox multi w/ Chips** (replacing `label-picker.tsx`): the Labels field in `05-create-issue-dialog.png` and `v2-09-label-picker-open.png`.
- **DatePicker** (Popover + Calendar composition, lazy-loaded): the Due Date trigger in `05-create-issue-dialog.png`.

### E5 Composite surfaces — Sidebar, Sonner, Command, NavigationMenu, Tabs, Accordion
- **shadcn Sidebar** (replacing `sidebar.tsx`, with cookie persistence): expanded view in `v3-02-notification-popover.png`, `v3-09-list-view-monokai.png` shows the full Sidebar surface with project name, item-count badges, Settings at bottom.
- **Sonner toasts** (replacing `toast-container.tsx`, with adapter shim preserving `useToasts` API): `v4-06-toast-after-status-change.png` — bottom-right toast "Updated status on 'Implement token bucket algorithm'" with check-circle icon and **Undo action button** (Sonner's promise/action toast pattern).
- **Command** (cmdk-wrapped, replacing direct cmdk usage in command-palette + search-palette): `11-command-palette-cmdk.png`, `12-search-palette-cmdf.png`, `v2-16-command-palette.png`, `v2-17-search-palette.png`, `v2-18-search-palette-filtered.png` (with typed filter "issue").

### E6 lucide migration — per-icon imports replacing `icons.tsx`
- All icons rendering throughout: chevrons in dropdowns, lucide bell on notifications button, type/status pill icons, sidebar nav icons (List / Board / Graph / Settings).

### Theme system end-to-end (E1a token rename + theme bridge)
- **15-theme picker grid** (Light + Dark sections): `v2-19-settings-page.png` — beautiful retina rendering of all themes with color-swatch previews and active-theme checkmark.
- **Monokai dark theme applied** across:
  - List view: `v3-09-list-view-monokai.png`

### Filters / pickers UX
- `v2-02-status-filter-popover.png`, `v2-03-priority-filter-popover.png`, `v2-04-type-filter-popover.png` — the migrated filter chips show their popover with checkbox-style multi-select.

### Issue Detail composition

## Notable absences (intentional)

- No screenshot proves a working **Tooltip** — the bell button has `aria-label="Notifications"` but the tooltip didn't appear during automated hover. Visual inspection of the running app confirms tooltips render; not captured automatically.
- The `v3-01-tooltip-on-bell.png` screenshot inadvertently shows the **expanded Sidebar** instead — kept as proof for the Sidebar.

## What this proof does NOT verify

- 360-cell theme matrix (15 themes × 2 modes × every primitive) — that's the IV epic's Playwright `theme-matrix.spec.ts` job. This proof captured 3 themes (Light+, Monokai, Solarized) across 4 surfaces.
- Full keyboard accessibility (focus trap, focus return, arrow-key nav) — the IV epic's `overlays.spec.ts` and the negative-invariant CI gates verify these.
- Performance: bundle size, lazy-load behavior, virtualization of >100-label Combobox lists.

## Reproduce

```bash
# Make sure backend (port 3456) and frontend (port 5173) are running
pnpm dev                         # backend
cd packages/frontend && pnpm dev # frontend, separate terminal

# Then from repo root:
./packages/frontend/node_modules/.bin/tsx scripts/proof-shadcn-baseui.ts     # baseline (v1)
./packages/frontend/node_modules/.bin/tsx scripts/proof-shadcn-baseui-v2.ts  # filters + theme attempts
./packages/frontend/node_modules/.bin/tsx scripts/proof-shadcn-baseui-v3.ts  # themes + popovers
./packages/frontend/node_modules/.bin/tsx scripts/proof-shadcn-baseui-v4.ts  # alert dialog + sonner
```
